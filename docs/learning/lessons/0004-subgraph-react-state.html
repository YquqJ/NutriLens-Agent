Subgraph：外层调度，内层 ReAct

对应 agents/graph.py 与 agents/diet_agent.py。目标：看懂一个 worker 为什么既是外层图的节点，又是一张拥有内部循环的小图。

两层图

外层 supervisor 图
START → turn_reset → analyze_image → summarize → supervisor
                                                   ↓
                              diet_agent 子图 → supervisor

diet_agent 子图
agent(调用 LLM) → tools(执行工具) → agent → tools → ... → END

ReAct 到底循环什么

  1. Think：LLM 根据任务和消息决定下一步；内部推理不等于必须输出思维链。
  2. Act：LLM 产出 tool call，例如 search_food。
  3. Observe：工具执行后追加 ToolMessage，其中是数据库或业务函数的结果。
  4. 若最后的 AIMessage 没有 tool call，子图结束；若有，就回到 agent 节点。

它会改状态吗

会，但不是模型直接改 Python 字典。每个节点返回一个 state update，由 LangGraph 按 reducer 合并。

  • messages：追加 Human/AI/Tool 消息，保存 ReAct 的行动与观察。
  • task、recognized_foods：由外层节点预先写入，子图读取。
  • remaining_steps：子图内部的 ReAct 步数保护；它不是业务字段。
  • 数据库记录是工具产生的外部副作用，不等同于把一项数据写进 AgentState。

一次记录请求的状态轨迹

HumanMessage: “午餐吃 100g 鸡胸肉”
Supervisor update: task=独立任务, hop_count=1
AIMessage: tool_call(search_food)
ToolMessage: 食物库结果
AIMessage: tool_call(create_diet_record)
interrupt: checkpoint 保存，等待前端确认
resume: 工具继续，service 写库
ToolMessage: 实际落库结果
AIMessage: 最终汇报
回到 Supervisor：决定 FINISH
最重要的面试表述：模型负责提出行动，工具负责执行确定性能力，LangGraph 负责状态合并、循环控制与中断恢复。
