QA Agent：可控的 Agentic RAG

对应 agents/qa_agent.py、rag/retriever.py、rag/citations.py。目标：掌握“检索质量、回答生成、引用可信度”三层边界。

它不是 ReAct 子图

普通 LangGraph 节点 qa_agent(state)
  → retrieve(query)
  → LLM 自检（QaSelfCheck）
  → 不足：query 改写 + 再 retrieve
  → 合并去重
  → 再自检
  → 充分：带证据生成
  → 清理并重编引用
  → 返回 messages/tool_calls/citations

检索轮数由代码控制，最多两轮。这样比让模型自由决定“是否一直搜索”更容易限流、测试和解释。

逐段职责

  1. _question_from：优先使用 Supervisor 改写后的 task，解决指代和默认值；没有 task 才取最后一条 HumanMessage。
  2. retrieve：向量召回负责语义，BM25 负责字面；RRF 融合后再 rerank。前者求全，后者求准。
  3. QaSelfCheck：让另一个非流式模型判断证据是否真的够用，并在不足时产出 rewritten_query。
  4. _context_block：把切片格式化成带编号的证据上下文，保证模型看到正文和来源定位。
  5. gen_llm：只有证据足够时才生成最终答案；生成模型不负责发现知识库缺口。
  6. normalize_answer_citations：只保留正文真正引用的证据，删除无效 [n]，重新连续编号。

为什么要拒答

如果第一轮和改写后的第二轮都不足，返回固定的 _NO_EVIDENCE_REPLY，并且不调用生成模型。这个“宁可拒答，不用通用知识补全”的策略，是 RAG 降低幻觉的核心护栏。

引用不是装饰

检索结果只是候选证据；最终引用必须来自回答正文实际使用的编号。后端把结构化 citations 同时放进 AgentState、SSE、messages.citations，前端据此把正文中的 [1] 渲染为可点击证据，而不是自己解析来源字符串。

面试要说清：引用编号校验只能证明“引用的切片属于本轮召回结果”，还不能完全证明回答中的每句话都被切片蕴含。后者需要 entailment 评估或人工/模型评审。

当前实现的工程亮点

  • 检索、自检、生成三阶段职责分离。
  • 向量 + 关键词混合召回，减少单一路径漏召回。
  • rerank 失败时回退粗排结果，不让非核心服务故障拖垮整条问答链。
  • 无证据时硬拒答，且测试断言生成模型没有被调用。
  • 检索轨迹结构化返回，支持 SSE、历史回放和调试。

需要继续改进

当前自检仍依赖 LLM，可能误判“充分”；引用校验也没有验证事实蕴含。生产可增加最低相关度阈值、领域分类器、答案-证据 entailment 检查和离线评估集。知识库内容还应视为不可信数据，提示词中明确要求忽略切片里的指令，防止检索内容注入。

自测

  1. 为什么要先混合召回，再 rerank，而不是直接把所有命中喂给模型？
  2. 为什么第一轮自检不足后，第二轮检索完成还要再次自检？
  3. 无证据时为什么不能让生成模型“凭常识回答”？
  4. 当前引用校验解决了什么问题，又没有解决什么问题？
