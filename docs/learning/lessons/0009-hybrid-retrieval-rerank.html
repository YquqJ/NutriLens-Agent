Hybrid Retrieval：召回、融合、重排

对应 rag/retriever.py、rag/rerank.py。目标：能解释 RAG 检索链的每一层为什么存在，而不是只说“用了向量数据库”。

全链路

用户 query
  → embed_query(query)
  → vector_search(query vector, top_k * 2)
  ─┐
   ├→ keyword_search(query, top_k * 2)
  ─┘
  → RRF 融合候选
  → rerank(query, candidates)
  → top_k evidence chunks
  → qa_agent 自检 / 生成

知识库中的一条切片

KnowledgeChunk 存正文、向量、来源文档、页码、章节和片段序号。正文与 embedding 服务于检索；来源元数据服务于可核验引用。KnowledgeDocument 单独存源文件信息，因此重导入时能按文件哈希幂等更新。

第一路：向量检索

embed_query 把 query 转成 1024 维向量；PostgreSQL pgvector 以余弦距离排序，距离越小语义越接近。HNSW 索引用于在大规模向量里近似快速找邻居。

“怎么瘦下来”
  ≈ 向量相近
“减脂应保持适度热量缺口”

优点是语义泛化；缺点是专有名词、数字型号和罕见术语可能不稳定。

第二路：BM25 关键词检索

中文没有天然空格分词，本项目把文本切为二元字符 token："减脂期" → ["减脂", "脂期"]。BM25 根据 query token 在切片中的匹配情况打分。

“BM25 算法”
  → 字面命中 “BM25 是基于词频的经典检索算法”

优点是精确命名和字面命中；缺点是不懂同义改写。知识库只有千级切片，因此每次在内存重建 BM25 索引比维护增量缓存更简单。

为什么不能直接相加分数

向量路使用余弦距离，通常越小越相关；BM25 分数通常越大越相关。它们的值域、含义、分布不同，直接加权需要人为校准且会随数据变化失效。

RRF：只融合排名

score(chunk) = Σ 1 / (K + rank)
K = 60，rank 从 1 开始
切片向量排名BM25 排名RRF 直觉
A：蛋白质摄入11两路都认为相关，最靠前
B：热量缺口2无保留为语义候选
C：BM25 原理无2保留为字面候选

RRF 不要求两路的原始分数可比；它奖励“多路都排得靠前”的内容，也不会丢弃某一路独占但仍可能有价值的候选。

为什么先多取，再 rerank

retrieve(..., top_k=4) 会先调用 hybrid_search(..., top_k=8)。前半段扩大候选池，优先保证 Recall；reranker 看 query 与候选正文的成对相关性，再从 8 条精排回 4 条，优先提升 Precision。

一句话：召回模型擅长快而广地“找可能相关”；reranker 擅长慢一些但更精确地“判断哪个最能回答这个问题”。

失败与降级

rerank 调用外部服务，超时或限流时，retrieve 捕获异常并退回 RRF 排名。系统选择“质量略降但可回答”，而不是让整个 QA 链路失败。

但 embedding 失败尚未降级到纯 BM25；这是当前实现可改进处。另一个问题是裸 except Exception 会遮蔽故障原因，生产应记录结构化日志、指标和错误类型。

如何测试

  • test_vector_path_semantic_recall：口语 query 能否找回“减脂”内容。
  • test_keyword_path_literal_match：BM25 能否命中 “BM25”。
  • test_hybrid_fusion：两路都召回的目标应靠前，并保留 ranked_by。
  • test_rerank_relevant_first：蛋白质相关切片应排第一。

面试表达

“RAG 检索我把 Recall 和 Precision 分层处理：向量检索覆盖语义改写，BM25 覆盖专有词和精确字面；两路原始分数不可比，因此用 RRF 融合各自排名。先扩大候选集保证召回，再由 cross-encoder rerank 精排到有限上下文，最后才给 LLM。rerank 故障时降级为 RRF，但 embedding 失败应继续补纯 BM25 降级和可观测性。”

自测

  1. 为什么 vector_search 中是按 cosine distance 升序，而不是降序？
  2. 为什么 RRF 不直接使用 BM25 分数与向量距离？
  3. 为什么最终要先取 top_k * 2 候选，再重排成 top_k？
  4. rerank 服务失败时为什么仍能返回 RRF 结果？embedding 服务失败时又该怎样降级？
