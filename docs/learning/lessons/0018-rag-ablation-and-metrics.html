RAG 量化提升：不要追数字，要做可复现的消融实验

目标：设计一条能写进简历、也经得起面试追问的 RAG 优化过程。核心词是 baseline、固定评测集、一次只改一个变量、记录代价。

先校正当前项目状态

你的代码现在已经不是最初级版本：

document_loader.py：按页码/章节识别，再以 600 字符 + 80 重叠切片
retriever.py：向量检索 + BM25 → RRF
retrieve()：混合候选 → rerank → top-k
eval.py：Recall@K / MRR / nDCG + 正负例观察

因此简历故事不应是“我准备实现 RRF 和 rerank”，而应是“我把检索管线拆成可对比阶段，并用 golden set 量化每个阶段的收益与代价”。

推荐的实验版本

版本变化目的
B0固定字符切分 + 向量检索建立最初基线
B1章节感知切分 + 向量检索验证边界和上下文是否改善
B2B1 + BM25 候选验证精确术语召回能力
B3B2 + RRF 融合验证两路排名融合收益
B4B3 + rerank验证精排对 top-k 准确性的收益
这里的 B2 “+ BM25 候选”和 B3 “+ RRF”需要在代码中提供实验模式。当前正式入口已经在 hybrid_search() 中做了 RRF，在 retrieve() 中做了 rerank；不能把现有实现误报成尚未完成。

PDF 要不要增加？

需要增加，但不是越多越好，也不能在每个版本随意增加。

  1. 当前 1 份 PDF、13 页、约 66 个 chunk，足以验证代码链路，但容易让指标看起来过于乐观。
  2. 最终评测可准备 3～5 份同领域、不同主题和写作风格的权威文档，并加入容易混淆的相邻主题作为干扰项。
  3. 一旦开始比较 B0～B4，语料库必须冻结。不能 B0 用 1 份 PDF，B4 再加 5 份，然后把差异全算给 rerank。
  4. 新增文档后要重新生成 chunk、embedding 和相关 hash；旧评测集中的证据标识也要校验。

评测集才是数字的地基

当前 rag_queries.json 有 47 条问题：42 条正例、5 条库外负例。它已经是起点，但建议扩充并分类：

类别例子为什么需要
直接问法“TDEE 由什么组成？”基础召回
同义改写“每天消耗总热量怎么算？”测试语义检索
术语精确匹配“DIAAS 和 PDCAAS”测试 BM25/关键词路
多证据问题同时需要碳水和蛋白质两片段测试 Recall 与 nDCG
库外问题股票、汽车、Python测试误召回和拒答

调参时使用开发集；最终数字使用冻结的测试集。否则你会不断根据题目调系统，最后得到的是“记住题目”，不是泛化能力。

“召回率 90%”到底是什么意思？

必须写完整口径，例如：

Recall@8 = 0.90
语料版本：nutrition-v2
评测集：rag-test-v1，正例 50 条
相关证据：人工标注的 relevant_hashes
统计方式：所有正例 Recall@8 的平均值

不要只写“召回率达到 90%”。还要说明是 Recall@4 还是 Recall@8，是平均值还是命中率，以及评测集有多少题。

“准确率提升 30%”为什么容易被追问？

“准确率”可能指检索命中、最终回答正确、引用正确或拒答正确。建议改成可验证的表述：

向量基线：Recall@8 = 0.72
RRF 版本：Recall@8 = 0.86
绝对提升：+14 个百分点
相对提升：(0.86 - 0.72) / 0.72 = 19.4%

如果你测的是答案，应使用“答案正确率”或“引用支持率”，并给出人工标注规则。没有真实前后数据，不要提前承诺“提升 30%”。

别只看分数：记录成本和副作用

改动可能收益可能代价
切片更小/更多重叠减少边界漏召回chunk 数、索引和上下文 token 增长
BM25 + RRF术语召回更稳两路检索耗时、重复候选
reranktop-k 精度更高额外 API 延迟、费用、失败降级
增加 PDF覆盖面更广干扰项增加，错误召回可能上升

面试里说出“指标提升但 p95 延迟、token 和成本也要记录”，比只报一个漂亮百分比更像真正做过工程优化。

推荐落地顺序

  1. 冻结一套最终语料和 rag-test-v1，先跑出 B0 基线。
  2. 给检索器增加实验模式，输出每个版本的 Recall@4/8、MRR、nDCG、负例 top1 分数、延迟。
  3. 只改切分策略，跑 B1；只改关键词候选，跑 B2；再启用 RRF，跑 B3；最后启用 rerank，跑 B4。
  4. 对每次变化保存配置、指标、逐题结果和失败案例。
  5. 最后再做答案级评测，区分“检索找到了”与“回答说对了”。
