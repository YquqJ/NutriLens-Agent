State 与 Graph：Agent 的共享工作台和流程骨架

本课目标：看懂 backend/app/agents/state.py 与 graph.py 的职责，并能解释一次请求如何路由、暂停、恢复。

一句话模型

State = 共享工作台
Node = 做一件事并返回状态更新
Edge = 固定流程
Command = 动态跳转 + 状态更新
Checkpoint = 保存状态和执行位置
interrupt/resume = 暂停 / 继续

读代码顺序

  1. 先看 AgentState 的字段，不要先背类型语法。
  2. 再看 _turn_reset，理解哪些字段是“本轮临时数据”。
  3. 再看 build_graph 的节点和边，画出执行路径。
  4. 最后看 get_checkpointer，理解跨请求和 HITL 恢复。

必会解释

模型只提出建议；图决定流程；工具和 service 负责确定性规则与副作用。
  • messages 使用 add_messages，新消息追加而不是覆盖。
  • thread_id 把多次请求绑定到同一条可恢复执行。
  • interrupt() 首次暂停并保存状态；Command(resume=value) 用同一 thread 继续。
  • 真正写数据库应放在 interrupt 之后，避免恢复时重复副作用。
