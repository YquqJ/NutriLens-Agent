RRF：把两份排行榜合成一份

对应 retriever.py:75-85。目标：不用死背公式，能看懂这十行代码在做什么。

先忽略算法名

向量检索和 BM25 各自交出一份“相关切片排行榜”。RRF 的规则只有一句：一个切片在每份榜单里排名越靠前，获得的分越多；在两份榜单都出现，就把两份分相加。

手算示例

向量榜：A 第 1，B 第 2
关键词榜：C 第 1，A 第 3

每次贡献 = 1 / (60 + 名次)
A = 1/61 + 1/63 = 0.03227
B = 1/62          = 0.01613
C = 1/61          = 0.01639

最终：A 第一，C 第二，B 第三

你不需要记住小数。只需知道：A 被两条路认可，因此压过了只被单条路认可的 B 和 C。

对应代码逐行翻译

代码人话
fused = {}准备一个“按 chunk id 汇总成绩”的成绩册。
for hits in (vec_hits, kw_hits)依次处理向量榜和关键词榜。
for rank, chunk in enumerate(hits)遍历这份榜单：拿到第几名和对应切片。这里 rank 从 0 开始。
setdefault(chunk.id, ...)成绩册没有该切片就新建；已有就取出来，方便累计另一条路的得分。
score += 1/(60+rank+1)加上当前榜单贡献；+1 是把 0-based rank 改成真实第 1 名、第 2 名。
ranked_by.append(...)记录它被哪条路召回，用于调试。
sorted(..., key=-score)按总分从高到低排出最终候选。

60 是什么

RRF_K = 60 是常用平滑常数。它让第 1 名和第 2 名的差距不会过于悬殊，重点奖励“多路都认可”。面试中说“RRF 的常用平滑常数”足够，不必推导来源。

故障降级纠正

若 embedding 服务失败，不能走向量检索，因为 query 无法转向量；应该直接运行 keyword_search，返回 BM25 的 top-k。若 rerank 失败，向量和 BM25 已经完成，因此可以回退到 RRF 排名。

当前阶段只需精读三段：vector_search、keyword_search、hybrid_search。SQLAlchemy 的查询语法、pgvector 索引细节和 Python 容器 API 先作为“认识即可”的支撑知识，不要求逐行背。
