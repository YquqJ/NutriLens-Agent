Exercise Agent：风险分级、降级与可追溯性

对应 agents/exercise_agent.py、tools/exercise.py、services/exercise.py。目标：从与 diet_agent 的差异中抽象 ReAct Worker 的通用设计。

运行路径

Supervisor task
→ exercise_agent ReAct 子图
→ create_exercise_record(type, duration, met=None)
→ Tool 查 MET_TABLE
  ├─ 命中：Service 用当前体重 + 公式计算 kcal，写库
  └─ 未命中：返回 met_not_found
              → LLM 按强度估 met，仅重试一次
              → Service 计算 kcal，写库
→ ToolMessage
→ LLM 最终汇报

为什么没有 HITL？

饮食运动
食物和克数常来自图片/模型估算，用户可能需要修改。类型与时长通常由用户直接陈述，例如“慢跑 30 分钟”。
写库前 interrupt 确认。当前策略直接写库，不 interrupt。

结论不是“饮食要 HITL，运动永远不要”。HITL 是按数据来源、误差风险和副作用后果选择的控制点。若运动时长也来自设备识别、语音转写或模型推断，就可能需要确认。

MET 的三层分工

  • exercise_agent：决定何时调用 Tool、拿到未命中提示后如何按规则重试。
  • Tool：先查表；未命中不直接写库，而是返回 met_not_found 给模型。
  • Service：依据给定 MET、用户体重、时长，执行确定性公式并写入业务记录。
calories_burned = MET * weight_kg * duration_minutes / 60

模型不能自己心算热量；它只有“选择工具”和“在数据缺失时给受约束的 MET 估计”的有限自由。

两种降级不要混

故障/缺失当前行为性质
MET 表未命中Tool 返回提示，LLM 估一个 MET 再重试业务降级，结果不确定
用户没有体重档案Service 使用 65kg 默认值并写入当时计算结果业务假设，结果不确定
历史记录之后用户改体重不重算旧 calories_burned保持历史不漂移

为什么热量要在写入时固化？

用户今天 70kg 跑步，三个月后变成 65kg。历史运动消耗应反映“当时按 70kg 的估算”，不能随着 Profile 更新变成另一数字。因此记录保存 met 和 calories_burned，编辑时仅按时长比例缩放，而不重新读当前体重。

当前可改进点

1. `ExerciseRecord` 没有 MET 置信度/来源字段，未来查询时无法区分“慢跑表命中 7.0”与“未知运动由模型估算 5.0”。可增加 `met_source=table|llm_estimate`。

2. 无档案默认 65kg 计算。Tool 返回值里有 `weight_used`，但应在最终汇报或记录 UI 中清晰标注默认假设，并优先引导补充体重。

3. `duration_minutes` 的 Tool 入参没有 Pydantic 数值范围约束；生产中应限制正数和合理上限，而不能完全相信模型或客户端。

通用 ReAct Worker 模板

class WorkerState(AgentState):
    remaining_steps: int

TOOLS = [read_tool, write_tool, delete_tool]

def prompt(state):
    return [SystemMessage(policy + task), *state["messages"]]

def make_worker():
    return create_react_agent(
        llm, TOOLS, prompt=prompt,
        state_schema=WorkerState,
    )

变化的不是骨架，而是 Tool 的数据来源、确认策略、权限、写入副作用和失败降级规则。

测试覆盖

测试分别验证 MET 查表和公式的纯函数、Tool 的创建查询删除、未知 MET 时不先落库、以及用户不能删除其他用户记录。Agent 集成测试还验证“慢跑 30 分钟”最终写入一条记录且全程不出现 interrupt。

面试表达

“我没有把 HITL 当成所有写操作的固定模板，而是基于数据可信度做风险分级：饮食克数常为估算，确认后写入；运动时长多为用户直述，直接写入。MET 先走确定性表，未命中才由模型按受限规则估计；消耗热量和用户身份都在 Service/运行时确定，写入时固化以避免历史随档案变化漂移。”

自测

  1. 为什么未知运动的 MET 未命中时，Tool 不直接按默认 5.0 写库？
  2. 用户之后体重下降，为什么旧运动记录的 calories_burned 不应自动变化？
  3. 若你添加 met_source，它解决了什么可观测或产品问题？
  4. 什么时候运动记录也应该增加 HITL？
