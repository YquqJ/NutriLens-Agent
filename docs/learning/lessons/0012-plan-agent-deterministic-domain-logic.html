Plan Agent：模型编排，程序计算

对应 agents/plan_agent.py、tools/profile.py、services/profile.py。目标：掌握 Agent 中“语言模型与确定性业务逻辑如何分工”。

运行路径

Supervisor task
  → plan_agent ReAct 子图
  → get_profile
  ├─ 档案齐全 → 读取 BMR/TDEE/calorie_target → 生成计划
  └─ 档案缺失 → 询问缺失字段
                   → 下一轮 update_profile(partial update)
                   → service 重算指标
                   → 读新档案并生成计划

为什么它仍是 ReAct 子图？

步骤不是完全固定：用户可能只想更新体重，也可能要计划；档案可能完整、缺一项或全空；用户可能在对话中补充多个字段。因此模型可以决定何时调用 get_profile、何时调用 update_profile、何时追问。但它只能在 PLAN_TOOLS 的受控能力范围内行动。

不可交给模型的数字

责任归属原因
判断用户要更新档案还是出计划LLM / plan_agent自然语言理解和沟通
调用 get_profile / update_profileLLM 选择 Tool有限的可控行动
BMR、TDEE、热量目标profile service 纯函数公式固定，必须准确、可测、可复现
档案和计算结果持久化service + database用户长期数据的唯一事实来源
把数字转成饮食、运动计划LLM表达、个性化建议和结构组织
原则：模型可以“解释计算结果”，不应“成为计算器”。健康、财务、权限、价格、库存等确定性事实都应由代码或可信系统产生。

Service 中的纯计算

BMR = 10 * weight_kg + 6.25 * height_cm - 5 * age + sex adjustment
TDEE = BMR * activity factor
calorie_target = TDEE + goal adjustment

缺任何关键数据时，recalc_profile_metrics 返回三个 None，不做猜测。比生成一个看似精确但无依据的数值更安全。

部分更新为什么重要？

用户说“我最近 68kg 了”时，只能更新 weight_kg，不能把未提及的性别、目标、过敏偏好覆写为空。updates.model_dump(exclude_unset=True) 的语义是：只修改模型明确传入的字段，类似 REST 的 PATCH。

update_profile({ weight_kg: 68 })
→ service 设置新体重
→ 基于完整档案重算 BMR/TDEE/target
→ commit + refresh
→ 返回最新档案

长期记忆与会话记忆

  • AgentState.messages / checkpoint：当前或近期会话执行上下文。
  • UserProfile：跨会话长期业务记忆，如身体数据、目标、过敏和偏好。

档案不应该只存在聊天摘要里，因为 REST 表单、Agent 工具和未来其他服务都要读写同一份用户事实。

身份边界

get_profile() 与 update_profile() 没有暴露 user_id 给 LLM，而是从运行时 config 取当前认证用户。这样模型无法请求或修改其他用户档案。

测试在验证什么

test_plan_agent_generates_plan_from_profile 不只断言有一段文本；它验证 Agent 先调用 get_profile、计划引用 service 算好的热量数字，并照顾“花生过敏”偏好。这才是在测工具使用和业务正确性。

代码阅读提醒

`tools/profile.py` 的文件注释写“plan_agent 与 qa_agent 共用”，但当前 `qa_agent.py` 并没有导入这两个 profile tool。以实际 import 和调用链为准，注释也可能过时。

面试表达

“计划生成允许 Agent 以 ReAct 方式完成读档、补档和交付，但 BMR/TDEE/热量目标由 Service 层纯函数计算并持久化。Tool 参数采用 partial update，未提及字段不覆写；user_id 从运行时注入而非模型参数。这样模型负责自然语言编排，代码负责确定性事实、权限和长期记忆。”

自测

  1. 为什么 `plan_agent` 需要 ReAct，而 `qa_agent` 的检索流程更适合显式编排？
  2. 用户只说“体重改成 68kg”，为什么不能把整个 Profile 当作完整表单覆盖？
  3. 为什么关键字段缺失时返回 `None` 比猜一个 BMR 更好？
  4. AgentState/checkpoint 和 UserProfile 分别属于什么类型的记忆？
