Diet Agent：一个受约束的 ReAct Worker

对应 agents/diet_agent.py、tools/diet.py、services/diet.py。目标：解释 Agent 为什么既需要工具调用自由，又不能拥有关键业务的最终控制权。

运行路径

Supervisor task
  → dynamic prompt
  → ReAct 模型选择 search_food
  → ToolMessage 返回营养事实
  → ReAct 选择 create_diet_record
  → interrupt 暂停
  → Command(resume=确认数据)
  → service 写库
  → Agent 汇报

先区分三层

  1. Agent：决定用什么工具、如何表达结果。
  2. Tool：暴露给模型的受控能力；从运行时读取 user_id，组装 HITL。
  3. Service：确定性数据规则和数据库读写；REST 与 Tool 共用。

为什么还需要 messages

task 告诉 Agent 目标；messages 记录 Action/Observation。例如模型调用 search_food 后，必须通过 ToolMessage 知道是否命中、营养值是多少，才知道下一步怎样调用写入工具。

最重要的可靠性原则

模型决定“要不要查库、怎样组织回复”；程序决定“事实是什么、能否写库、何时暂停、是否允许继续”。
  • 识图在前置节点完成，避免历史污染导致漏调视觉工具。
  • 营养数据来自食物库，模型估算须明确标为 llm_estimate。
  • 过敏检查在工具与 service 两层执行。
  • 写库在 interrupt() 之后，防止 resume 重放导致重复副作用。
