# RAG 量化提升与消融实验

用户希望在简历中写“召回率 90%、准确率提升 30%”，并计划通过增加 PDF、改切分、混合检索、RRF、rerank 逐步提升。

本节关键纠正与方案：

- 数字必须绑定完整口径：指标名称（如 Recall@8）、语料版本、评测集版本、正例数量、平均/命中统计方式。不能只写“准确率”。
- 当前项目已经具备章节感知切分、向量 + BM25、RRF 和 rerank；下一步应增加可切换实验模式，做消融对比，而不是把现有能力写成未来计划。
- 推荐 B0 固定字符+向量，B1 章节切分+向量，B2 加 BM25 候选，B3 加 RRF，B4 加 rerank。每一阶段只改变一个主要变量。
- 增加 PDF 有助于泛化和干扰项，但比较版本时语料必须冻结；新增文档会改变 chunk、embedding 和 relevant hash，不能把语料变化造成的收益归因给算法。
- 当前评测集 47 条（42 正例、5 负例）可作为起点；应补同义改写、术语精确匹配、多证据问题、库外问题，并保留冻结测试集，避免调参泄漏。
- 召回指标之外还要记录延迟、token、API 成本、rerank 失败率和逐题案例。高 Recall 不代表最终回答正确，还需答案级 faithfulness、引用正确率和拒答准确率。
- 简历可写“设计可复现的 RAG 消融评测管线”；只有真正跑出前后数据后，才写 XX→YY，且区分绝对百分点和相对百分比。
