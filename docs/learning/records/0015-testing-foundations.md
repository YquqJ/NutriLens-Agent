# 测试入门：从 AAA 到测试结果含义

用户明确表示测试基础接近零，需要在 Agent 测试与 Eval 前先补测试本身。

本节建立的前置概念：

- 测试是把业务/技术承诺编码成可重复执行的自动检查，主要用于防回归，不等于系统正确性的数学证明。
- 一条测试用 AAA 组织：Arrange（准备）、Act（执行）、Assert（比较）。
- `pytest` 发现 `test_` 测试，运行断言；断言为真则 passed，为假则 failed，前提不具备时可能 skipped。
- `passed` 仅表示给定输入符合给定预期；`skipped` 表示未执行，不能算通过。
- 预期的可靠性来自明确业务规则/公式、手算或独立观察、正常与边界/异常场景覆盖，而不是从被测函数复制同一段逻辑。
- 项目中的 `mrr` 指标函数是最合适的第一个例子；过敏 Service 测试体现“用实际数据库状态检查禁止副作用”。
